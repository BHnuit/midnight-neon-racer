## 2. 设计语言的取舍

目标不是复制 1980 年代桌面系统，也不是给赛道叠一层滤镜，而是把 TaiT CRT 的构图纪律翻译成游戏 UI：

**Hans 于 2026-08-18 选择 B：游戏界面为主，只借 TaiT 的设计语言。** 正式菜单不是电脑桌面模拟器，不复刻操作系统；玩家第一眼应先看懂当前车辆和可执行动作，再感受到复古 CRT 气质。

1. 菜单统一使用 `游戏01` 五色、2 px 母网格、硬边方窗、位图字和不等宽面板；不使用圆角、渐变、抗锯齿阴影。
2. 每屏只有一个主窗口、一个次窗口和必要的小控件；保留 20%–30% 连续背景场，不把每段文字都装进同尺寸卡片。
3. CRT 桶形畸变、扫描线、噪点和同步错位只出现在菜单视觉层的外缘 10%；中心 80% 稳定，所有可点击控件完整落在稳定区。
4. 局内画面保持平直像素渲染，不加 CRT 畸变、扫描线或桌面窗口隐喻。
5. TaiT 生成稿若用于风格锚点，原始成稿保留其固定签名，只存 `assets/minigame/previews/` 作审稿证据；运行时素材独立重制为模块，不裁切、涂改或直接发布生成稿。
6. 菜单不放无功能的系统菜单栏、假下拉框、假光标、桌面图标或说明性装饰文字。窗口标题、按钮和状态只承载现有产品信息。
7. TaiT 的窗口、标题栏、点阵、外缘 CRT 信号和不对称层级是视觉语法，不是额外玩法；不能为了“像电脑”降低车辆、主动作或游戏状态的优先级。

## 3. 坐标、安全区与触控

### 3.1 坐标契约

- 设计画布：`720×1280`。
- 本文 UI 坐标使用 Cocos 中心原点：左为负 X，下为负 Y。
- 所有位置、尺寸、九宫格边距和位图字基线均取偶数，落在 2 px 母网格上。
- 固定格式控件必须有明确宽高；文字出现、选中态和反馈动画不能推动相邻布局。

### 3.2 两层安全区

| 区域 | 基准范围 | 规则 |
| --- | --- | --- |
| 设备 SafeArea | `x=-336..336`，`y=-592..600` | 仅作 9:16 回退值；运行时以设备安全区和 `Widget` 为准 |
| CRT 稳定交互区 | `x=-288..288`，`y=-512..512` | 菜单所有完整点击框必须落在这里；外缘只放装饰、标题溢光和信号故障 |

场景应增加全屏 `SafeArea` 节点，并在窗口尺寸变化时刷新。视觉菜单可以全屏渲染到 CRT 表面，命中层保持稳定坐标；由于控件都在中心 80%，视觉与命中不应产生可察觉偏差。

### 3.3 触控基线

- 主要和次要按钮最小命中框 `88×88`。
- 图形箭头可视像素可小于 88，但节点命中框保持 `88×88`。
- 按钮间净距至少 16；不使用只有文字本身可点的热区。
- 菜单状态变化只改颜色、边框、1–2 格位移或 2 px 抖动，不让控件改尺寸。

## 4. 菜单公共合成栈

从下到上：

| order | 节点 | 职责 |
| ---: | --- | --- |
| 0 | `CRTBackdrop` | 全屏夜色底和连续开放场，不承载文字 |

| 20 | `WindowChrome` | 主/次窗口、标题栏、1–2 px 内外框、少量棋盘格 |

| 50 | `CRTSignal` | 外缘桶形、扫描线、噪点、一次同步错位；中心区不得模糊文字 |

每屏窗口数量控制在 3–6 个视觉单元。棋盘格只用于一条标题栏或一个角落，占屏不超过 6%；不能把全部空白填成纹理。

## 5. 菜单逐屏几何

以下保留 ADR 0007 的信息顺序：发车进门，选车只换车并返回，说明独立，只有发车页能开局。调整只解决安全区、命中框和文字拆分。

### 5.1 发车页 `title`

**2026-08-19 试玩调整覆盖旧大车窗：标题是第一视觉层，车辆展示降为辅助层。** `CarStage` 固定为 `520×224`，车辆素材安全框为 `220×104`；车身、尾光和接地影不得越过窗口内边距。标题必须先于车辆被识别，禁止把车窗重新放大成首页主角。

**展示角度选择 B：车尾三分之四。** 五辆车各自生产一张独立发车展示图，朝向保持一致，车尾和单侧车身同时可见；它不是选车页侧视图，也不是局内正后视精灵。五张图必须共用底中锚、视角、像素密度和 `220×104` 外框，切换车辆时不得跳位。

**展示窗背景选择 A：五车共用霓虹公路发车线。** 背景是独立的 `488×184` 窗内图层，只画夜城、向远处收束的空道路和近处发车线；不含车辆、交通、文字或按钮。道路消失方向保持固定，切车时背景不更换、不跳视角。

**待机动画选择 B：低强度、低频率。** 展示窗允许尾灯呼吸、远处灯牌偶尔闪烁和车身最多 `2 px` 的怠速轻摆；道路、发车线和镜头保持静止。动画不播放引擎声，不改节点外框，不影响按钮命中，并尊重系统静音与后续的“减少动态效果”开关。

### 5.2 选车页 `select`

**Hans 于 2026-08-18 选择 C：左右滑动和箭头同时支持。** 两种输入只调用同一个 `selectCar(index)` 入口；切车结果、锁定态和反馈完全一致。滑动只在选车页启用，横向位移达到 `48 px` 且绝对横移至少为绝对纵移的 `1.25` 倍时翻一辆；一次手势最多翻一辆，不按甩动速度连跳。切换演出期间忽略重复输入，不在画面上增加操作说明。

**首尾行为选择 A：循环。** 索引统一按五辆车取模；第一辆向左进入第五辆，第五辆向右进入第一辆，箭头和滑动的视觉方向保持连续。左右箭头在边界仍可用，只在切换演出的短暂输入锁期间进入禁用态。

**未解锁信息选择 B：只公开名称、剪影和解锁里程。** `CarArt` 使用正式侧视图生成单色剪影，不另做一套车辆素材；`Quote`、`SpeedCell`、`PipCell` 和图鉴正文隐藏，但各窗口外框保持原尺寸。`ConfirmButton` 显示里程条件并禁用；解锁后在同一槽位恢复正式内容，不推动布局。

**切车过渡选择 B：2–4 帧 CRT 信号错位。** 效果只裁在选车内容窗内：旧内容产生最多 `4 px` 水平错位，中央用一条深色同步带完成数据替换，新内容随后归位，总时长 `120–160 ms`。不做车辆滑入、全屏白闪、亮度脉冲或连续噪点；过渡开始后锁输入，结束后才接受下一次翻页。该效果用节点裁切与位移完成，不为五辆车另出过渡帧。

### 5.4 结算页 `result`

**第一批结算决策：`1B 2A 3B 4C 5A`。** 结算页使用 4 张同框结果小图；每次进入默认打开“本局”；分数在约 `0.8 秒` 内快速逐项揭示；好友页固定显示前三名，并在本人不在前三时追加本人名次；局内结果演出结束后用 `2–4` 帧 CRT 信号切入结算。

- 碾压：Magenta，持续 480–700 ms，允许 2–3 帧水平抖动。
- 命格损失：对应命格先亮 Magenta，再在 120–180 ms 内熄灭；不推动其余图标。
- 路程分：只更新总分数字，不产生燃烧跳字。
- 命中停顿若采用 30–80 ms，只暂停世界模拟；HUD、输入和屏幕转场使用非缩放时间。

### 6.3 字体

- `HUD 数字/英文`：6×8 或同等密度 BMFont，以 2 px 单元绘制；主分数可整数倍放大。
- `菜单中文`：制作固定中文子集 BMFont，覆盖 `ui-copy.md`、按钮、全部结算句和昵称空态。
- 字号档只用 `20/24/32/40/48` 设计单位，行高分别固定；不随视口宽度连续缩放。
- 静态 Label 使用 BITMAP 缓存，动态分数/计时使用 CHAR；禁止字体缺字时悄悄回退到抗锯齿系统字。
- 构建前用 glyph manifest 检查正式文案的所有字符。

### 7.2 场景、天空与地表接续

- 月亮在整局进度 55%–75% 淡出，太阳在 62%–82% 淡入；允许短暂同屏，禁止一帧互换。天气滤镜贯穿交接，不随路段重新抽取。
- GroundBase 的内边必须与每个道路采样点左右缘贴合，外边至少越过左右画布边缘；从最远采样到屏幕底部都不得露透明像素或只靠一张远景剪影硬撑。
- 正式路段素材应提供可独立调色/透明度的 Sky、Far、Mid 与 GroundBase，不得把天空、楼脚、地表和道路烤成一张全屏图。

## 9. 代码结构优化方案

不引入全局 UI Manager、通用事件总线或抽象屏幕框架。只按已经出现的变化轴拆分：

```text
GameDirector ── DirectorView + RunEvent[]
      │
MainController                 # 生命周期、输入、组合根、屏幕切换
  ├── MenuView                 # title/select/help 固定槽与文字适配
  ├── ResultView               # 本局/好友页签与空态
  ├── RunRenderer              # 道路、天气、车辆投影和深度排序
  ├── HudView                  # 固定 HUD 槽，只读 snapshot
  └── FeedbackView             # 只消费 RunEvent，管理短生命周期反馈
```

### 9.1 数据边界

- `RunSession` 继续是唯一局内规则真相；UI 不保存一份分数、命格或技能规则。
- `GameDirector.tick()` 把本帧 `RunEvent[]` 原样交给 Cocos 适配层。`FeedbackView` 按 `graze/crush/damage/fail/...` 触发演出，不从 snapshot 差值反推事件。
- `HudView` 只读稳定 snapshot，分别更新 Pips、Skill、Score、Combo、Speed、Elapsed 节点。
- 方向若改变，先扩 core 数据契约和测试，再改 renderer；不在渲染器里用 sprite 名猜方向。

### 9.2 Cocos 热路径

- `onLoad` 缓存节点、组件、BMFont 和图集引用；`update` 内不再 `findChild/getComponent`。
- 对 score、speed、elapsed 做“值改变才写 Label”；避免每帧重建长字符串和临时数组。
- 交通节点按 `TrafficKind + facing` 建池，离场 reset 后回池；碎片和跳字分别建小池，不能把不同生命周期对象塞进一个池。
- `RunRenderer` 只接受投影后的 view model，图层顺序由节点树固定，不靠每帧改 sibling index 补救。
- UI 坐标常量留在 `assets/scripts/cocos/`，不进入纯规则 core。

### 9.3 场景修改方式

正式实施时通过 Cocos MCP 的 scene/node/component/label/composite 工具建立节点和挂载组件，不手改 `.scene`、`.prefab`、`.anim` 或 `.meta`。适合批量修改的同类节点先用 composite/builder 方案一次提交，再用 validate 和 capture 验证。

## 10. 车流方向决策门

### 10.1 决策背景（已关闭）

早期基线把 10 种交通都当作迎面来车，且 `TrafficSpec` 没有方向和独立速度字段。这证明把车图换成背面不是美术调整，而是玩法、数据、计分、文案和测试的共同变更。该决策门现已关闭，当前实现为 C。

### 10.2 三个可选方案

| 方案 | 手感 | 与现有契约 | 美术成本 | 主要风险 |
| --- | --- | --- | --- | --- |
| A. 全迎面（早期基线） | 高频正面压迫、晚躲清晰、偏闪避动作 | 完全一致 | 每类只做正面 | “整条路都逆行”削弱 OutRun 的超车感，速度层次较平 |
| B. 全同向 | 超车、尾流、相对速度更像经典公路赛车 | 重做擦车与多份 ADR/文案 | 每类只做背面 | 当前核心卖点“脸上要撞再让开”失效 |
| C. 路段级混合（推荐验证） | 普通段追车，明确的逆行窗口制造晚躲高潮 | 保留迎面擦车，但需新增车流契约 | 每类正背两套，近似翻倍 | 若视觉预告不足，会让玩家误判规则 |

**Hans 于 2026-08-18 选择 C：路段级混合。** 色块验证与正式规则修订均已完成：

- 65% 同向追车段：车有独立速度；普通远距超车不计分，贴近完成超越算一次擦车并进入连击。
- 25% 迎面挑战段：整段方向明确，晚躲才计擦车和连击。
- 10% 低车流恢复/景观段：给路形、天气和技能读条留呼吸。
- 方向按路段统一，不在同一条无分隔三车道上随机混正背车。入口至少提前一个屏深给出路面箭头、灯光朝向或中心线变化。

以上比例只是原型调参起点，不是最终生成权重。U1 混合车流色块已通过，交通正背两套素材、危险段车道组合与节奏边界已经锁定；Gate 6 仍未解除，因此不批量生产。

### 10.3 已接受的换向过渡

换向使用一套稳定玩法语法、三种可混用的场景外皮：

| 外皮 | 画面解释 | 使用限制 |
| --- | --- | --- |
| 可变车道换向门 | 龙门架箭头变色、移动护栏打开跨线口 | 默认通用版本，适用于开放道路 |
| 施工借道 | 锥桶、围挡和斜向导流标把玩家带入对向道路 | 作为专用换向段，不与普通施工或路形变化叠加 |
| 隧道换向 | 入口预警，隧道内部遮住道路横移，出口进入危险段 | 只用于种子路中已有足够间隔的隧道主题 |

无论使用哪种外皮，都按同一顺序演出：

1. 同向车流逐渐减少，保留约 2 秒空路。
2. 远处换向标志由 Cyan 切为 Magenta，路面和护栏开始导流。
3. 玩家保持完整横移控制；道路只做视觉横移，不强制转向或播放不可控过场。
4. 进入约 1.5 秒无车缓冲；继续用路面箭头、护栏开口和灯光方向确认换向，不显示 HUD 路况词。
5. 第一辆独立迎面车用明显双头灯报信，随后才进入正常车流。
6. 离开危险段时反向执行，再恢复同向车辆。

外观可以变化，但预警颜色、空路缓冲、第一辆报信车和输入规则不能变化。换向段作为独立 segment kind，不与 ADR 0010 的普通施工、大桥、隧道、土路随机叠放。

当前原型进一步锁定运行时隔离：同向车只在 `normal/thinning/warning` 激活，并在 warning/crossing 中沿最近一侧出口平滑偏离道路；`crossing/buffer` 不激活新车，`sentinel/danger` 只允许迎面车。同向车的正常退场不播放撞飞碎片、不计分；任一 snapshot 中两种方向的交通数量不得同时大于 0。正式换向素材必须给左右侧出口、遮挡或导流设施留出视觉解释，不能只靠车辆横着消失。

### 10.4 已接受的危险段车道规则

**Hans 于 2026-08-18 选择：三条车道都可能出现迎面车，但每一波必须可解。**

- 不设永久安全车道；可通过通道可以在不同波次之间换边。
- 每个 encounter wave 必须至少留下一个连续通道，宽度按五辆玩家车中最宽碰撞体校验。
- 双车道大巴占两道时，剩余车道在完整反应窗口内不得再生成、横扑或摆入另一辆车。
- `weave/lunge` 可以压缩选择时间，但不得在低于晚躲最小反应时间时封死最后通道。
- 普通车辆不开技能也必须能通过；飞行、碾压和氮用于提分或降低难度，不能成为种子可解性的前提。
- 生成后执行确定性可解校验；失败则重排该波，不在运行时临时删车。固定 seed 必须得到固定波次和固定可解结果。

### 10.5 已接受的危险段时长

**Hans 于 2026-08-18 选择：每个危险段保持 20–25 秒有效迎面车流，目标 4–6 个 encounter wave。**

- 20–25 秒从第一辆报信车之后、正式车流开始时计，到退场清流开始时结束。
- 进入与离开的换向演出不计入危险段有效时长。
- 前两波用于建立节奏，中间 2–3 波组合车种，最后一波形成小高潮；不能第一波就投放双车道大巴加横扑车。
- 波间保留短呼吸，不把 20–25 秒填成连续车墙。
- 具体波数可随速度和选车碰撞宽度在 4–6 内调整，但固定 seed 与车辆选择必须产生可复现结果。

### 10.6 已接受的一局频率

**Hans 于 2026-08-18 选择：一局约 5 分钟出现 3 次危险段。**

- 有效迎面车流合计约 60–75 秒，占整局约 20%–25%；其余时间以同向追车、超车和低车流恢复为主。
- 第一段不得出现在开局教学与起跑后的首个稳定巡航段；三次之间必须有完整同向段隔开。
- 三次分别承担“认识规则、组合变化、末段高潮”，不能只把相同波次复制三遍。
- 精确落点由固定种子决定，但要满足最小间隔和终点前退场距离；不能把最后一次换向演出挤进结算前几秒。

### 10.7 混合车流的 core 契约

当前原型已落地为下列稳定键；正式素材和调试工具直接使用这些名字，不再另造一套 `flow/facing` 同义字段：

```ts
type TrafficDirection = 'same' | 'oncoming';
type FlowPhase = 'normal' | 'thinning' | 'warning' | 'crossing' | 'buffer' | 'sentinel' | 'danger';
type TransitionStyle = 'gantry' | 'detour' | 'tunnel';

type TrafficSpec = {
  direction?: TrafficDirection;
  waveId?: string;
  // id / kind / lane / atDistance...
};

type RoadSegment = {
  curve?: number;
  hill?: number;
  // start / end / lanes / theme / kind...
};

type FlowZone = {
  start: number;
  end: number;
  phase: FlowPhase;
  style?: TransitionStyle;
  dangerIndex?: number;
};
```

- 车流已改为逐车速度：车型给出基准 km/h，每辆车在固定 seed 下生成确定性 ±10% 差异。车辆在 `1800` 前视边界激活后，同向按「交通车速 - 玩家车速」、迎面按速度之和积分相对位移。
- 晚躲危险时间改以当前相对距离 / 实际闭合速度计算；同向车速高于玩家时不得进入「即将超车」威胁态。
- 两种方向都发统一 `nearMiss` 事件并带 `NearMissKind`。迎面子类型沿用晚躲判定；同向子类型必须完成“后方→近距包络→前方”，仅并排行驶或远距超越不触发。
- 同一交通 id 只进入一次统一已结算集合；两个子类型共用现有连击窗口和 200 / 300 / 400 / 500 阶梯。
- `ActorSnapshot` 已明确给出 `direction/hidden/lightCue/worldX/transitioningOut`，渲染器不从 sprite 名推断方向；迎面画白色头灯，同向画红色尾灯，换向退场只消费 core 给出的横向世界坐标。
- `ROAD_VERSION` 已升到 4；固定种子、逐车速度、方向段、4–6 波、最宽车可解通道、超车、迎面擦车、换向方向隔离和弯坡投影已有测试。
- `来车` 这个总称若包含同向车辆，应统一改为 `车流` 或 `路车`；所有 UI、图鉴 brief 和失败句逐项复核。

同向计分与道路曲率/坡度范围已经确认并实施。ADR 0011、道路几何契约和 core 测试是当前规则真相；ADR 0004 只继续定义迎面晚躲子类型，不再作为全车流范围。

## 11. 如何借鉴两份 OutRun 实现

只借行为模型和分层方法，不复制代码或资产。

研究基线：[jakesgordon/javascript-racer](https://github.com/jakesgordon/javascript-racer)、[ZgzInfinity/OutRun](https://github.com/ZgzInfinity/OutRun)。

### 11.1 可借

- Jake Gordon 版本用 `enter / hold / leave` 和 easing 组织直道、弯道、坡度的段落过渡；本项目可把同一方法用于路宽、路边密度、天色和主题过渡，避免路段边界硬切。
- 该版本用玩家速度占比、车辆独立速度和前视避让形成同向交通节奏；若车流选择 B/C，可借“相对速度 + 可预判侧移”的设计问题，不照搬其全局变量实现。
- 两份实现都把道路段数据、投影、车辆和菜单/HUD 分开，并由远到近投影、由近到远反向绘制；本项目已有 RoadFactory/RoadProject 基础，只需稳定 UI 与 renderer 边界。
- ZgzInfinity 版本把交通 AI 区分为温和、避让和障碍等意图；现有 `weave/lunge/police` 可以继续作为小而明确的行为特征，不需要先造行为树。

### 11.2 不借

- 不加入方向盘、手动挡、刹车、离心甩车或轮胎物理；跟手横移继续是唯一转向输入。
- 不复制 Jake 项目的音乐或占位精灵；其 README 明确这些素材不属于可随代码复用的交付。
- ZgzInfinity 项目为 GPL-3.0。当前项目只把它当行为研究资料，不复制其实现到产品代码。
- 不照搬桌面分辨率、键盘输入、比赛模式和完整菜单树。

### 11.3 已接受的道路几何范围

**Hans 于 2026-08-18 选择：加入真正的 2.5D 左右弯和上下坡，不加入岔路。**

- `RoadSegment` 增加有符号曲率和目标高程，使用 `enter / hold / leave` easing 平滑进入、保持和退出。
- `RoadProject` 沿连续路段积分道路中心和高度；路面、车辆、路边卡片、消失方向与背景视差共同变化，不用一张弯曲贴图假装转弯。
- 车辆横向位置改为“相对当前道路中心的偏移”。玩家仍然拖到哪里车就去哪里，不因弯道自动向外漂移。
- Camera A 保留为玩家附近的基准构图；远处消失方向可随曲率移动，地平线可随坡度变化，但玩家车锚点和 HUD 不跟着漂。
- 一条种子路仍是从头到尾的必经路线，没有岔路、选路提示或不同路线长度结算。
- 先在隔离色块原型验证投影、遮挡和移动手感，再替换现有直线投影；不在同一次修改里同时接正式素材。

需要新增的纯规则测试至少包括：弯道连续性、坡顶裁切、车道中心相对坐标、固定 seed 可复现、路边深度排序，以及最宽玩家车在弯坡上的可解通道。

### 11.4 已接受：危险段与弯坡完全混合

**Hans 于 2026-08-18 选择完全混合，并明确“撞了就是命”。**

- 三次危险段都可以与急弯、上坡顶、下坡和复合弯坡重叠，不要求第一段先放在直路教学。
- 坡顶和弯内侧可以遮住具体来车，不保证每辆车出现后都留下足够的视觉反应时间。
- 换向门仍会明确告诉玩家“已进入逆行危险段”，但它不预告每辆隐藏车辆的位置。
- §10.4 的可解约束继续存在：道路揭示后必须有一条几何可通过通道，不能生成三车道同时封死；“来不及看见”可以发生，“根本没有路”不可以发生。
- 这类碰撞按正常重量、保险杠、飞行和碾压规则结算，不额外减伤，也不从种子中临时删车。
- 固定 seed 必须固定隐藏车的位置。重开同一 seed 后，玩家可以靠记忆规避；随机性不在运行时偷偷改答案。

### 11.5 已接受：隐藏来车使用环境弱提示

**Hans 于 2026-08-18 选择：用环境暗示，不显示 HUD 警告，也不保证足够躲开。**

- 每个被道路完全遮住的 encounter 至少选择一种视觉暗示：弯后头灯染光、坡顶天际线闪光或护栏短反光。
- 短促喇叭、发动机逼近声可以作为第二通道，但静音时视觉暗示仍必须存在。
- 不显示方向箭头、危险图标、倒数或文字；提示不直接暴露具体车道。
- 暗示可以很晚，目标是营造“前面可能有东西”，不是承诺可反应窗口。
- cue 类型、出现时机和隐藏车辆都由同一 seed 决定；重开不得换提示骗玩家。
- 视觉 cue 属于 `FxBack/世界光照`，音频 cue 属于独立反馈实例；任一反馈被性能降级都不能改变车辆生成和碰撞结果。

生产资产增加：弯内侧路面染光 1 组、坡顶轮廓闪光 1 组、护栏反光 2–3 帧、近/中/远三档喇叭或发动机声。全部为可复用模块，不烤进单张道路背景。

### 11.6 已接受：同向贴近超车进入擦车连击

**Hans 于 2026-08-18 选择：只有贴近完成的同向超车计分，并与迎面晚躲共用擦车连击。** 玩家动作和玩家用语统一，决定见 [ADR 0011](adr/0011-mixed-flow-graze.md)。普通提前换远车道的超越只改变道路位置，不得分；同一目标最多记一次。

### 12.1 过线标准

- 五屏信息顺序与 ADR 0007 一致，正式文案无缺字、截断或临时改写。
- 菜单看得出同一套 CRT 像素系统，局内没有 CRT 污染。
- HUD 在最大值下不位移；技巧反馈不覆盖车辆、计时或失败标题。
- 阴影/尾光永远在车后，碎片/闪光在车前，演员深度顺序稳定。
- 交通正背素材、道路预告和玩法方向完全一致，不出现“画面同向、规则迎面”的混搭。
- 换向进入时先完成同向车侧向退场，再出现迎面报信车；没有穿车、混流或把正常退场误画成碰撞。
- 场景边界、日月交接和地表承接无硬切、悬空或透明露底；全程仍只有一组道路消失点。
- 不手改 Creator 序列化文件，不把预览锚点、签名稿或外部项目素材打进微信包。
